# 布局修复与交付停止条件

首次生成候选前读取一次。后续沿用本轮结论，不为每次改图重读。需求确认、方案先行、50 mil 格点和真实引脚检查继续执行。

## 生成前确定布局

- 已有复用模块布局清楚时保留，只适配必要接口。新画电路按输入→处理→输出安排主通道，外围属于相应芯片，GND 默认向下；方向按实际引脚与拓扑调整。
- 按需使用 drawing-patterns 中匹配的范例，先规划模块 origin/size、主要器件位置、母线、属性文字区域和模块间距，再编写 place/connect。统一位号和值的位置，给长型号、电源名称、测试点文字预留空间。布局不改变方案中的器件、参数和网络。
- 简单单电源 LDO 默认一个功能框：输入接口及输入电容→稳压器→输出电容及输出接口；LED、预载及测试点仅在方案要求时加入。VIN/VOUT 各自电容靠近对应侧，支路并排接地，避免为装饰拆成多个框。三脚 1117、带 EN 的 LDO 和多输出器件分别按真实引脚处理，不能强套 VIN/EN 范例或改写物理脚号。
- 必要字段先保持可读；可见 Value 允许使用明确的短型号/容值，完整采购型号保留在器件属性和方案中。不得为缩短文字丢失影响识别的数值、极性或关键额定参数。

## 一次检查，集中修复

1. 首版直接生成实际候选，读取整图确认页面与分区；文字确实无法辨认或有定位问题时再读对应 regionImages。不重复读取同版本图片，不为已返回区域编写裁图脚本。
2. 在本轮工作记录中汇总已发现的具体问题：模块/位号或网络、实际影响、对应修改。记录可是一句简短说明，不新增审计文件或用户审批。完成检查后一次修改受影响的脚本、属性或区域，避免“改一处→构建→读图→再改下一处”。
3. 简单项目默认“首版→一次集中修复→验证并交付”；首版已达标则直接交付，不能为了走满轮数重建。修复版只复核修改区域、受影响连接及整页范围，沿用其他区域的检查结论。
4. 超出一次集中修复时，必须先指出仍存在的具体阻塞缺陷、对象、影响和下一次修改方法，再修复。明确错连/漏连、格点错误、裁切或无法辨认始终允许继续修；不得因达到轮数就交付有已知错误的工程。同一缺陷两次修改仍未解决时改用更宽区域或不同走线通道，不能反复微调同一偏移。

## 必须继续修复与应当停止

| 检查项 | 交付条件 | 必须继续处理 |
| --- | --- | --- |
| 文件与格点 | 工具可生成并渲染；实际引脚、器件原点及连接点符合 50 mil | 格式错误、未解析引脚、SCHEMATIC_OFF_GRID 或其他真实构建错误 |
| 连接意图 | 实现已读回方案的器件/引脚/供电/关键网络；无已知错连或漏连 | 方案与实现不一致、极性错误、必要连接缺失；修复时同步方案 |
| 视觉表达 | 关键型号、数值、引脚和接点可辨认，文字不造成网络或器件归属误读 | 遮挡关键引脚/接点、文字无法区分、内容被裁切 |
| 页面与分区 | 外框完整、模块归属清楚、不侵入标题栏或其他模块 | 器件/关键文字越框、模块互相侵入而影响阅读 |
| 工程与说明 | 所需本地库齐全，正式版本与方案、脚本一致，限制如实说明 | 缺库、脚本未持久化、实际实现与文档矛盾 |

上述条件满足后立即进入发布、清理与正式概览，不再做纯装饰修改。轻微不对称、空白大小不同、文字仍清晰但“挪一点更好看”、可辨认的字号或间距差异，不单独触发新候选。用户明确要求版式精修时按其要求处理。

layoutWarnings 和 planPowerPlacements.diagnostics 是保守提示：同一批已判断不影响阅读的警告可以保留，不追求警告数量归零，不为追踪已确认的边界重叠另写 UUID/几何分析脚本。警告为 0 也不自动证明连接正确、图纸可读或完成电气验证。仅按已有必要资料和工具结果检查，不因此增加默认 ERC、XML 网表比对或几何审计。

## 收尾只做一次

候选满足条件后发布到固定 project/，完成必要库检查、方案回填和本轮清理，再调用 delivery:true。同版本正式预览可复用缓存；不要为了用户看到概览再额外读图。正式概览是最后一个工具操作，然后直接输出交付说明。不得为了每一项可选美化建议重新打开已经完成的布局循环。
