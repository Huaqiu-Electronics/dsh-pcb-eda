# PCB 铺铜

目标是在当前板子上完成用户要求的铜区创建或填充，并报告已确认的结果。使用 `dsh-kicad` 的 KiCad IPC 能力；不把 FreeRouting 的走线完成当作铺铜完成。

## 工具与边界

- 先加载 `kicad-ipc` 技能，遵循其连接、读取、事务与验证方法；先通过 `kicad_ipc_diagnose` 确认当前 PCB。诊断本身不提供完整板框和铜区清单；需要时按该技能的公开 `kipy` 接口在会话工作区编写只读检查脚本，不修改随包模板。
- `kicad_pcb_create_copper_zone` 接收已存在的 `net`、启用的 `layer` 和按顺序排列的毫米坐标 `points`，只创建未填充多边形。它不提供板框自动内缩、孔洞、圆弧、热焊盘、优先级或间距参数；不能虚构参数，也不能声称这些设置已生效。
- `kicad_pcb_refill_zones` 填充当前板上的已有区域，不是仅填充本次新建的区域。工具完成通知不是完整连通性或设计规则检查结论。
- 写入串行执行；与布线互斥。用户同时要求布线和铺铜时，等待布线及其收尾实际结束，再重新读取板子。未知写板结果或未释放占用时，不继续写入。
- 所有工具使用 `save:false`，除非用户明确要求保存。填充失败保留原有走线和已确认创建的铜区；不要为了重试重新创建或清空板子。

## 选择操作

1. 读取当前板名、启用铜层、精确网络名、已有铜区的 UUID/网络/层/边界，以及实际板框和内部挖空。不能用磁盘中的旧 PCB 代替编辑器内的未保存状态。
2. 用户只要求重新填充且板上已有铜区时，直接填充；无铜区则说明缺少铜区，转到创建需求。已有匹配铜区时优先复用，不因重复请求叠加相同铜区。
3. 创建前确定网络、铜层和范围。沿用本轮已明确的设计要求；“铺铜”“布线并铺铜”不自动代表双面 GND、整板或内缩 0.5 mm。对影响结果的缺失项一次简短询问；网名不存在时报告候选，不新建网络或把 AGND/DGND/PGND 自动合并。
4. 多层板仅操作用户指定且启用的铜层。已有不同网络、重叠区域、锁定区域或分割电源时，保留原设置；需要改变优先级、间距或已有区域时，先核对所需公开 API 和精确作用范围。常见分支见 [references/common-cases.md](references/common-cases.md)。
5. 用户指定多边形可直接核对后创建。整板范围必须基于有效、闭合的实际板框；不要用包围矩形替代异形板、缺口或孔洞。仅当已有公开原生能力能保留边界和挖空时生成几何。边界不明、板框不闭合或当前工具不能表达需要的形状时停止创建，说明需要明确多边形或补充原生能力；不现场编造通用几何算法。
6. 记录操作前目标与已有铜区 UUID，调用创建工具，保存返回 UUID，并重新读取核对网络、层和边界。多层创建由多个独立事务完成，不承诺“一次撤销所有铺铜”。部分成功时报告已创建和未创建的层；结果未知时先重读，不盲目重试或删除。
7. 创建核验后再填充，重新读取目标铜区状态。不能确认填充、出现超时或编辑器断开时，明确报告未知或失败，保留诊断；不把“发出请求”当成“填充完成”。

## 回复用户

使用已确认事实说明：本次新建或复用了哪些网络/层的铜区，填充是否完成，哪些操作未完成，以及是否保存。没有执行 DRC 或连通性检查时不承诺规则通过、无孤岛或全部接通。

布线与铺铜一起请求时分别报告两个结果；布线任务卡成功只代表布线任务。若铺铜需要澄清，先说明布线的实际结果，再询问缺失信息，让用户知道剩余工作尚未执行。
