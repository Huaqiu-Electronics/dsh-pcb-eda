# 硬件产品需求文档（PRD）

PRD 定义产品可交付和可验收的结果。先从 MRD 场景或用户直接给出的产品目标出发，追问决定产品架构和可测试性的缺口：

- 功能边界、典型/异常使用流程、模式、通道数、响应时间、精度、速率和容量。
- 输入电源范围、功耗与续航目标、输出负载、上电/掉电行为及故障状态。
- 外部接口、协议、连接器、线缆、兼容对象，以及固件/软件对硬件的要求。
- 外形和安装边界、环境条件、寿命、可靠性、维护与升级方式。
- 安全、EMC/ESD、无线和目标市场的适用要求；认证目标与验证状态分开。
- 成本目标、生产批量、制造/测试/维修要求和上市时间。

建议将 `docs/02-hardware-PRD.md` 组织为：产品概述与范围、用户场景、系统边界、需求表、接口定义、机械与环境边界、成本/制造约束、验收与验证、待确认事项。需求表的每一项尽量包含：编号 `H-001`、来源 MRD 编号（若存在）、要求、优先级、状态、验收条件/方法。要求应可测量，并写明单位、工作条件和必要的容差；例如电源范围应区分正常工作、极限和故障条件。

PRD 可记录用户指定的核心器件或不可更改的实现约束，并说明来源；未指定时优先写功能、电气和接口要求，让具体器件选择留到 design brief。目标尚不明确时标记待确认，不用任意数值凑齐表格。涉及测试或认证的条目写为目标和验收方法，不宣称已经通过。
