# 初始布局算法：数据流、几何、搜索与失效模式

这份文档是 `pcb-initial-placement` 技能的实现说明。所有数字都来自对 KiCad `video`
示范板（189 器件 / 2118 焊盘 / 589 网络 / PCI 312×106.7 mm 板）的实测。

## 1. 数据流

一次运行的所有产物都落在**项目下的 `placement/`**（与板文件同级，不存在就新建）。技能目录
只有代码，cwd 不留任何东西。脚本默认就写在那里：知道 `--board` 的用 `<板目录>/placement/`，
其余用输入文件所在目录；`--outdir` 换目录，`--out` 精确指定文件名。

```
board.kicad_pcb  ──board_geometry.py(只读)──▶  placement/geometry.json
                                                ├ 每个器件的 courtyard 局部矩形 (+bbox_src)
                                                └ 板框闭合多边形 + 包围盒
                                                        │
placement/placement_config.json ──人的决策：模块/锚点/固定件/禁布区/顺序 ──┤
                                                        ▼
                                                    pack.py
                                                        ▼
                                          placement/placement_plan.json
                                                        │
              ┌──────────────┬──────────────┬───────────┼──────────────┐
              ▼              ▼              ▼           ▼              ▼
   verify_placement.py  placement_view.py  pose_table.py  apply_via_ipc.py
   （独立校验 →         （模块彩色视图 +   （交接位姿表   （首选：整批一个
    verify_placement    评估面板 →         CSV）          undo → apply_
    .txt，硬门槛）       placement_view.svg）              via_ipc.txt）
```

packer 完全不理解 KiCad 文件语法——它只吃矩形和多边形。唯一需要读板文件的地方是
"把某个焊盘钉在板边坐标上"（金手指），那时才用只读的 s-expression 解析器查一个焊盘。

`verify_placement.py` 与 `placement_view.py` 各自独立重算重叠/出板/密度，**不共用 packer
的代码**；两者都会把结果落盘。视图里的门槛数字只用于显示，判据始终是校验脚本。

## 2. 坐标与几何

### 2.1 旋转公式

KiCad 板面坐标 **Y 轴向下**，所以正角度是**顺时针**。局部坐标 `(lx, ly)` 绕原点转 `deg`
后在世界坐标下的偏移：

```
dx = lx·cos(θ) + ly·sin(θ)
dy = −lx·sin(θ) + ly·cos(θ)
```

这个式子在 video 板上用全部 2118 个焊盘逐点比对 KiCad 的实际落点验证过，**最大误差
0.000000000 mm**。它必须对，否则所有间距计算都是错的，而错误又小到看不出来。

用旋转后的四个角点做 min/max，得到该朝向下的轴对齐占用矩形：

```python
pts = [rot_pt(px, py, rot) for px in (x0, x1) for py in (y0, y1)]
box = (min(x), min(y), max(x), max(y))
```

### 2.2 占用矩形（courtyard）

重叠判据只有一个：**courtyard 层**的图形。取不到就按固定顺序退化：

```
CrtYd → Fab → 焊盘外扩 → 丝印(SilkS) → 零面积点
```

每个器件的来源记在 `bbox_src` 里，必须逐件点名——一个错误的 courtyard 会安静地毁掉整个
布局，而且看起来一切正常。

`video` 板 189 个器件**全部**有 courtyard，没有退化情形。但退化情形是真会出现的：一块
LibreSolar BMS 板（208 器件）上的两个丝印 logo 既没有 courtyard、没有 Fab 图形，也没有
焊盘——走到"焊盘外扩"那一步拿到 `None`，旧版 `board_geometry.py` 于是在汇总行
`r["bbox_local"][2]` 上抛 `TypeError: 'NoneType' object is not subscriptable`，整块板提不出几何。
现在的链路会在丝印层兜住它，标成 `bbox_src: "silk"` 并点名。

**零面积点是最后一种情况，也是最危险的一种**：器件没有任何可测几何，谁压它都不算重叠。
它会被单独警告，必须人工处理——不要当它已经放好了。

丝印不是电气层，用丝印推出来的框只影响外观与排布美观，不影响电气正确性；但**它仍然是
参与重叠判定和占位的真实矩形**，所以别把 logo 当成可以随便压的装饰件。

### 2.3 板内判定

射线法（奇偶规则）判断点是否在板框多边形内。注意边界点：点恰好落在某条边的 x 坐标上时
`x < x0 + ...` 为假，该边不计数，结果由另一侧的边决定。这不是 bug，但它意味着
**"正好在板边"是模糊的**，所以不能依赖它做安全边界——见 2.4。

### 2.4 栅格与半格腐蚀

- 栅格 `GRID = 0.635 mm`（25 mil，PCB 常用摆放步长）。
- 单元格可用当且仅当它的**中心**和**四个角**都在板内（角点向外偏 `GRID/2 + 1e-6`）。
  这把板框向内腐蚀了约半格（0.32 mm），保证任何合法位置的 courtyard 都不会压在板边外。

没有这一步会怎样：单元中心在板内、但矩形边压在板外，器件就"合法地"挂在板外。
实测中 R14 和 L6 就这样各挂出板外 0.2 mm 和 0.4 mm——2D 校验只查重叠，不查板框，
所以它们一路通过了所有检查。

## 3. 占用栅格与所有权

```
OCC[j][i]   = 1 表示这一格被占
OWNER[j][i] = 255      固定件 / 禁布区（不可驱逐）
            = 0..254   已摆放器件的 id（可驱逐）
```

三种状态各有用途：

1. **判空**：`rect_free(rect, gap)` 检查矩形膨胀 `gap` 后覆盖的所有格子。
2. **登记**：`mark(rect, gap, owner)` 盖章。
3. **驱逐**：疏散修复需要知道"这个位置挤到了谁"，靠 `OWNER` 反查；固定件返回 255，
   表示"碰不得，换个别的位置"。

两个必须遵守的细节：

- **盖章和判空必须用同一套取整。** 曾经一边用 `round()`、一边用 `int(v/GRID + 0.5)`，
  结果膨胀后的矩形溢出一格，覆盖了邻居的 `OWNER`，随后 `BY_IDX[owner]` 抛 `KeyError: 50`。
- **索引必须用 `math.floor`，不能用 `int`。** `int()` 向零截断：`int(-0.278) == 0`，
  于是"比板边靠外一点"的矩形被判成从第 0 列开始，而不是"越界，拒绝"。

**所有权 id 要回收。** 每 commit 一次就新分配 id，很快超过 255，`bytearray` 直接抛
`ValueError: byte must be in range(0, 256)`。正确做法是维护一个 `free_ids` 回收池，
`release(ref)` 时把 id 还回去并清掉该 id 占的格子。

`unmark(owner)` 遍历全栅格清除该 owner 的格子。这是 O(NX·NY)，每次调用约 3 ms
（337×170 栅格），在几千次调用的规模下可以接受。

## 4. 功能分块：证据链

### 4.1 连通性

从网表构造器件-器件权重矩阵。`video` 板的关键数据（互相连接的网数）：

| 器件对 | 共用网络数 | 结论 |
| --- | --- | --- |
| U11 ↔ BUS1 | 51 | PCI 总线接口核心，必须贴金手指 |
| U11 ↔ U24 | 47 | 总线控制器和主 FPGA 紧邻 |
| U24 ↔ U23 | 47 | 两个 FPGA 同区 |
| U11 ↔ U23 | 41 | 同上 |
| U22 ↔ 每个 SIMM | 32 | SIMM 控制器必须在帧缓存阵列旁 |
| U8 ↔ U9 | 37 | RAMDAC 与 encoder 同区 |
| U3–U6 ↔ SIMM | 各 8 | 总线缓冲排成一排贴着 SIMM |

这张表直接变成了 floorplan：U11 靠金手指、U24/U23/U22 靠 U11、SIMM 阵列靠 U22、
U3–U6 排成一列贴着 SIMM。

### 4.2 电源网络必须降权

`video` 板的电源扇出：**GND 115 个器件、+5V 70 个、+5F 5 个、+3.3V 3 个**。
如果按原始连通性聚类，整板会被 GND 并成一个巨大模块。

处理：把电源/地网从聚类权重里剔除；聚类完成后再把**只通过电源/地连接的 31 个器件**
（去耦、滤波电容）按电源域分给对应模块，并在报告里显式标注这是"归属不确定"的一类。

### 4.3 sheet 前缀

网名的原理图路径前缀是作者自己的功能划分，作为交叉验证：`/buspci.sch/` 73 条 →
BUS1/RR1–RR6/U11；`/graphic/` 32 条 → U2/U7/U21/U23/U24/X1 等；`/pal-ntsc.sch/` 4 条 →
U10 视频输入链；`/ESVIDEO-RVB/` 3 条 → U8/U9 输出链。

### 4.4 不变式

用断言守住两条，任何一条不成立就直接退出而不是继续跑：

```python
assert {全部模块的成员} == {板上所有器件的 ref}      # 恰好一个归属，无重复无遗漏
assert 每个模块至少有一个核心器件                     # 找不到核心说明分块有问题
```

`video` 板的结果：M1 20 / M2 30 / M3 36 / M4 40 / M5 47 / M6 16 = 189 ✓

## 5. 锚点与定位件

### 5.1 从板框反推封装原点

金手指封装的原点无所谓，但焊盘必须落在板边。找一个语义明确的焊盘（PCI 的 A1），
用它的局部坐标反推：

```
origin = 板边目标点 − 焊盘局部坐标
视频板：A1 局部 = (−62.865, −0.254)，目标 (95.25, 160.195)
        → BUS1 原点 = (158.115, 160.449)
```

### 5.2 结构偏移

`J4` 的封装名是 `DSUB-9_Female_Horizontal_P2.77x2.84mm_EdgePinOffset14.56mm_...`，
名字里的 14.56 就是"板边到原点"的距离 → `origin_x = 53.594 + 14.56 = 68.154`。

BNC 支架连接器同理：本体伸到板外 14.5 mm，原点压在板边内 4.4 mm。

**这些数字要来自板子和封装本身，不能凭印象填。**

### 5.3 机械禁布区

8 个 SIMM 插座排成 2 列 × 4 行，行距 14.5 mm，插座 courtyard 高 8.1 mm，行间只剩 6.4 mm。
模块插入后下倾约 30°，顶端水平伸出约 11 mm —— 会盖住行间区域。因此把行间登记为禁布区。

但要**同时算清代价**：`video` 板行间占用约 6.7 千 mm²，把它整块留空后剩下的板面
**放不下全部 189 个器件**。所以这不是"算法偷懒"，是板面密度的硬约束——这种情况要
把数字摆出来让用户选（改变安装姿态 / 换插座 / 接受小器件被压住），而不是自己决定。

## 6. 环形搜索

### 6.1 为什么是环形而不是行扫描

行扫描（从板子左上角逐行找第一个空位）会把器件甩到离核心很远的地方，彻底破坏分组。
环形搜索以**模块锚点**为中心，半径按 `coarse = 1.27 mm` 增长，每圈按角度采样，返回
**离锚点最近的合法位置**——它天然把器件聚在核心旁边。

采样密度 `n = max(8, 2πR/coarse)`：半径 30 mm 时每圈约 148 个点，点间距 1.27 mm。
**采样间距必须小于最小器件的短边**，否则会跳过窄缝里的合法位置（曾经用 3.81 mm，
大量器件因此找不到位置，只放下 102/189）。

找到候选点后在 ±3 格内做一次网格细化，把位置吸附到栅格上并取更优者。

### 6.2 多锚点

一个模块有多个核心时，对每个锚点各搜一次，取距离最近的那个解。所以一个模块的外围
器件会自然聚到"离自己最近的那个核心"旁边，而不是全部挤在一个点上。

### 6.3 半径阶梯

一个器件这一轮失败，下一轮给它更大的半径：

```
RADIUS = [30, 45, 65, 90, 130, 200]  mm
```

**不要在失败时直接跳到"板子任意位置"**。早期版本用了一个"最终溢出 pass"，
结果没放下的器件全部被倒到板子另一头，M4 模块的距离中位数被拉到 156 mm。

## 7. 模块顺序会决定成败（实测）

同一份算法，只改模块处理顺序，`video` 板的结果：

| 顺序 | 总距离 | 最大距离 | M4 中位数 | M5 中位数 |
| --- | --- | --- | --- | --- |
| `M1,M5,M4,...` | 10612 mm | 233.5 mm | **156.0 mm** | 43.2 mm |
| `M1,M4,M5,...` | **10445 mm** | **192.7 mm** | 67.7 mm | 113.7 mm |
| 轮流先手（rotation） | 10612 mm | 233.5 mm | 156.0 mm | 43.2 mm |
| M4 优先 + M5 补锚点 | 10496 mm | 186.2 mm | 67.7 mm | 110.1 mm |

结论：**顺序是超参数，必须实测**。评分用"每个器件到本模块最近核心的距离"的
中位数、最大值和总和——中位数反映典型分散度，最大值反映最坏飞地，总和反映整体。

轮流先手（每轮换一个模块先取）在这块板上没有改善，因为两个模块的需求量差距太大，
先手权不足以补偿。这条也说明：**直觉方案要验证，不能想当然**。

## 8. 疏散修复

板子密到一定程度，贪心一定会剩几个器件无处可放。这时不要降低间距（会破坏设计规则），
而是做**驱逐**：

1. 扫描全板，找所有"只压到可驱逐器件"的合法位置。
2. 代价 = 被驱逐器件的 courtyard 面积之和。
3. 代价最小的位置胜出；被挤走的器件重新入队。
4. 代价超过自身面积 2 倍时放弃——太破坏性的交换不值得。

`video` 板最终 189/189 全部落地，没有走"降低间距"这条路。

## 9. 向核心压实

全部落地后，按"离核心从远到近"排序，依次尝试把每个器件挪到"更靠近自己核心的合法位置"。

这一步**不可能破坏可行性**：候选位置必须通过同一套 `rect_free` 检查；找不到更近的
合法位置时就原地不动。所以它只能让分组更紧。

`video` 板实测：第 1 轮移动 4 个、第 2 轮 5 个、第 3 轮 0 个——3 轮内收敛到局部最优。

## 10. 复杂度与运行时间

- 栅格：337 × 170 ≈ 57k 格；`mark`/`rect_free` 只碰矩形覆盖的格子，典型 9×5。
- 环形搜索：最坏 200 mm / 1.27 mm ≈ 157 圈 × 每圈最多约 990 点 × 2 朝向，
  但绝大多器件在第 1–3 圈就命中。
- 疏散修复：全板扫描，`step=2` 降采样，只在剩下的少数器件上跑。
- **实测 `video` 板（189 器件）整个 pack 阶段约 200–220 s**（单线程 Python）。
  其中绝大部分时间在疏散修复和压实的全板扫描上。

单线程足够：这是一个几分钟量级的离线规划任务，不是交互式工具。

## 11. 已知失效模式速查

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 只放下 100/189 | 环形采样间距 > 器件短边，跳过窄缝 | `coarse` 降到 1.27 mm 或更小 |
| 少数器件被甩到板子另一头 | 失败后被送进"最终溢出 pass" | 改成半径阶梯，逐轮扩大搜索 |
| 报 `KeyError: <owner id>` | 盖章和判空取整不一致，矩形溢出覆盖邻居所有权 | 统一取整函数 |
| 报 `byte must be in range(0,256)` | 所有权 id 只增不回收 | 加 `free_ids` 回收池 + `release()` |
| 非连接器器件挂在板外 0.2–0.4 mm | 板内判定没做半格腐蚀 + `int()` 截断索引 | 四角判定 + `math.floor` |
| 某个模块整体散开 | 该模块在 round-robin 里排在后面，近处空间被先手模块占完 | 调整模块顺序并实测评分 |
| 器件"消失"但报告写着 0 未放置 | 失败的器件被静默丢掉，没有重新入队 | 失败必须 `append` 回队列 |
| courtyard 面积统计正常但布局很挤 | 没有考虑间距膨胀；courtyard + 0.6 mm 后占板 78% | 把膨胀后的面积算进密度预算 |
| 网表聚类把整板并成一组 | GND/+5V 没降权 | 电源网剔除权重，事后按电源域分配 |
| `TypeError: 'NoneType' object is not subscriptable`（提取几何时） | 器件既无 courtyard、无 Fab、无焊盘（丝印 logo），退化链拿到 `None` 后仍去索引它 | 退化链补上丝印兜底，并对"什么都没有"的件单独告警 |
| `IndexError: list index out of range`（校验分组时） | 某个模块成员全是固定件（安装孔、板边端子），`anchors` 为空表，却仍按 `anchors[k][0][0]` 取锚点 | 做距离/离群统计前先筛掉没有锚点的模块 |
| 计划里 28 个定位件，板子上一个都没动 | `apply_via_ipc.py` 默认跳过 `fixed`，而这块板的定位件也在停机坪上 | 零布局的板子必须带 `--include-fixed`；提交后实时读回全部位号核对 |
| 报告/视图数字对不上 | 两处各算了一套密度或重叠 | 判据只认 `verify_placement.py`；视图只复述 |

## 12. 视图生成（placement_view.py）

出图只依赖标准库——不引入 cairo、不调浏览器、不要求装 KiCad。理由是这张图必须在**分析
流水线内部**就能产出：一块提取不出几何的板子，也不该连张图都看不到。

几个刻意的选择：

- **自动比例尺**：`S = clamp(target_width_px / 板宽, 1.5, 14)` px/mm，默认把板子铺到约
  1500 px 宽；太小的板子不会糊，超长板也不会溢出。`--scale` 可覆盖。
- **画布按内容定尺寸**，不是拍一个高度。图例行数、指标行数、禁布区说明行数都先数出来，
  再算 `panel_h`——否则 14 个模块或 5 条禁布区的板子会把文字画出下边缘。校验方式很直接：
  解析生成的 SVG，确认**所有 `<text>` 的 y + 字号都在画布内**。
- **固定件实心、算法摆放半透明**：评审时要能把"我决定的"和"算法推出来的"分开看，这个
  透明度差就是那条分界线。
- **禁布区画成斜线填充并写出原因**：禁布区是决策，不是背景噪声。
- **调色板按模块名排序分配**，同一块板每次出图颜色一致；模块多于 12 个时循环取色，同时
  在 `bbox_src` 警告里点名，避免两个模块撞色后没人发现。
- 面板里的重叠对数、出板数等是**显示用**的：这里的算术只看计划文件，不读板。真正的判据
  是 `verify_placement.py`。
